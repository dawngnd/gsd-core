<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input -> router | `<change-id-or-phase>` and blocker text are untrusted. |
| NDD artifacts -> ship context | `CHANGE-SPEC.md`, `IMPACT.md`, `VERIFICATION.md`, and GSD verification artifacts may contain large or malformed Markdown. |
| Adapter -> canonical ship | NDD passes context to GSD ship but does not own PR creation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-02-01 | Tampering | `writeNddShipContext` | high | mitigate | Validate linked change/phase paths and write only `.planning/ndd/changes/<change-id>/SHIP-CONTEXT.md`. |
| T-07-02-02 | Elevation of Privilege | `commands/ndd/ship.md` delegation | high | mitigate | Delegate to canonical GSD ship after gates pass; do not run `gh`, mutate remotes, or create PRs from NDD helper/router/tests. |
| T-07-02-03 | Information Disclosure | `SHIP-CONTEXT.md` | medium | mitigate | Render concise summaries and links; do not embed full source documents. |
| T-07-02-04 | Repudiation | `markNddShipped` and blocked-state helper | medium | mitigate | Record `shipped_at` or blocker details in `STATUS.json` only through explicit helper paths. |

</threat_model>
