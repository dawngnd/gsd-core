# Summary: Plan 03-01 — Foundation Types and Capability Config

## What was built

- `gsd-core/ndd/codebase_capability.json` — Default tool capability config with 3 tool entries (codegraph, grep_search, wiki), each with available/config/capabilities fields
- `src/ndd-impact-discovery.cts` — Impact discovery module with:
  - 10 exported types: ImpactConfidence, DiscoveredBy, ImpactEntry, RequirementImpactGroup, ImpactAnalysisData, ToolCapabilities, ToolConfig, CodebaseCapabilityConfig, CodebaseMapAvailability, ImpactDiscoveryResult
  - `loadCodebaseCapabilityConfig(packageRoot)` — loads JSON config with frozen default fallback
  - `checkCodebaseMapAvailability(projectRoot)` — detects `.planning/codebase/*.md` presence
  - `extractRequirementSections(changeSpecContent)` — extracts bullet items from CHANGE-SPEC "Confirmed Source-Backed Requirements" section
  - `renderImpactMarkdown(data)` — renders IMPACT.md with YAML frontmatter, summary table, per-requirement impact groups, and cross-cutting section
  - Private `markdownTableCell()` helper for table cell escaping
  - Frozen `DEFAULT_CAPABILITY_CONFIG` constant
- `gsd-core/bin/lib/ndd-impact-discovery.cjs` — Compiled output (auto-generated by tsc build)

## Key decisions

- Wrote the complete module in one file creation rather than incremental tasks, since all functions are tightly coupled in the same module
- Used the same `import x = require('./y.cjs')` pattern from `ndd-change-intake.cts` for CommonJS interop
- `markdownTableCell` duplicated as a private helper (same 4-line implementation as in `ndd-change-intake.cts`) per plan spec
- Deeply froze `DEFAULT_CAPABILITY_CONFIG` (nested `Object.freeze()` on tools, each tool, and capabilities) for immutability
