- Check if `.planning/codebase/` directory exists under `projectRoot`
- If missing or not a directory: return `{ available: false, files: [], directory }`

### Task 3: CHANGE-SPEC Section Extractor

<action>
Add an exported function `extractRequirementSections(changeSpecContent: string): Array<{ id: string, title: string }>` to `src/ndd-impact-discovery.cts`.

Logic:
1. Use `tokenizeHeadings(changeSpecContent)` to parse section structure
2. Find the section with heading matching `Confirmed Source-Backed Requirements` (case-insensitive substring match)
3. Within that section's body, scan lines for bullet points matching pattern `/^[-*]\s+(.+)$/`
4. For each bullet, generate an `id` as `R${index + 1}` and use the bullet text as `title`
5. If no matching section or no bullets found, return an empty array (graceful fallback)

This function enables IMPACT.md to be grouped by CHANGE-SPEC requirement per Decision #8.
</action>

<read_first>
- src/ndd-impact-discovery.cts (the file being modified — current state after Task 2)
- src/markdown-sectionizer.cts (tokenizeHeadings return type and behavior)
- src/ndd-change-intake.cts (lines 433–683 for renderChangeSpec to see CHANGE-SPEC.md section headings)
</read_first>

<acceptance_criteria>
- `extractRequirementSections` is exported from `src/ndd-impact-discovery.cts`
- Given input with `## Confirmed Source-Backed Requirements\n\n- First req\n- Second req\n`, returns `[{ id: 'R1', title: 'First req' }, { id: 'R2', title: 'Second req' }]`
- Given input with no matching heading, returns `[]`
- Given input with matching heading but no bullet lines, returns `[]`

### Task 4: IMPACT.md Renderer

<action>
Add an exported function `renderImpactMarkdown(data: ImpactAnalysisData): string` to `src/ndd-impact-discovery.cts`.

Follow the pure string-array-joining pattern from `renderSourceManifest` / `renderChangeSpec` in `ndd-change-intake.cts`:

1. Build a `lines: string[]` array
2. Add YAML frontmatter block: `change_id`, `phase: impact-discovery`, `status: draft`, `created: <ISO timestamp>`, `tools_used: [<tools>]`
3. Add `# Impact Analysis: <change_id>` heading
4. Add summary table with columns `Confidence | Count` and rows for confirmed, likely, unknown (counts computed from `data.groups` + `data.cross_cutting`)
5. For each `RequirementImpactGroup` in `data.groups`, add section `## Impact: Requirement <id> — "<title>"` with a Markdown table: `File | Evidence | Source Ref | Discovered By`. If no entries, add a single row: `| None identified | — | — | — |`
6. Add `## Cross-cutting Impact` section with the same table format for `data.cross_cutting`
7. Return `lines.join('\n')`

Implement a private `markdownTableCell(value: string): string` helper (same 4-line implementation as in `ndd-change-intake.cts` line 185–190: replace newlines with `<br>`, escape `|` with `\|`, trim).
</action>
