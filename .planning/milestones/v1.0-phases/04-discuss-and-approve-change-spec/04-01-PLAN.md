<action>
Create `src/ndd-discuss-spec.cts` with:

1. **Types**: Define and export `AmbiguitySeverity` as `'critical' | 'non-critical'`, `ExtractedAmbiguity` with fields `text: string`, `severity: AmbiguitySeverity`, `section_ref: string`, `source_ref: string`. Define `ExtractedConflict` and `ExtractedOpenQuestion` with similar shapes. Define `DiscussionSeed` containing `ambiguities: ExtractedAmbiguity[]`, `conflicts: ExtractedConflict[]`, `open_questions: ExtractedOpenQuestion[]`, `impact_unknowns: Array<{requirement_id: string; title: string}>`.

2. **extractAmbiguities(changeSpecContent: string): DiscussionSeed**: Parse CHANGE-SPEC.md content using `tokenizeHeadings` from `./markdown-sectionizer.cjs`. Extract bullet items from `## Ambiguities`, `## Conflicts`, and `## Open Questions` sections. Tag each ambiguity with severity using `classifyAmbiguitySeverity()`. Return structured `DiscussionSeed`.

3. **classifyAmbiguitySeverity(text: string): AmbiguitySeverity**: Return `'critical'` when the ambiguity text matches implementation-changing keywords per D-12 (patterns like: architecture, api contract, data model, security, authentication, authorization, breaking change, migration, schema, endpoint, database). Return `'non-critical'` otherwise.

4. **extractImpactUnknowns(impactContent: string): Array<{requirement_id: string; title: string}>**: Parse IMPACT.md to find requirement groups with `confidence: 'unknown'` entries or empty entry tables. Return their requirement_id and title.

5. **buildDiscussionSeeds(changeSpecContent: string, impactContent: string | null): DiscussionSeed**: Combine extractAmbiguities output with extractImpactUnknowns output. Sort critical ambiguities first.

Import pattern: use `import { tokenizeHeadings } from './markdown-sectionizer.cjs'` and `import { platformWriteSync } from './shell-command-projection.cjs'` following the existing NDD module import conventions. Export with `export =` pattern matching ndd-impact-discovery.cts.
</action>

- `classifyAmbiguitySeverity('API contract needs clarification')` returns `'critical'`

- Module uses `export =` pattern consistent with ndd-impact-discovery.cts
</acceptance_criteria>
